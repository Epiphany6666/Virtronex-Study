# 代码分析

分析分支：`vtron_java_server` `dev`，`c61f995c7`（2026-11-18）。前两节是 `POST /api/v1/card/bins` 和 `POST /api/v1/card/choices`。创建见下面 `40098` 那一节。开卡费见最后一节。`bin_control` 怎么在后台改，归 `25-分销商代理与BIN`。费率配置页归 `21-费率与流水`。签名见 `19-OpenAPI会话`。

两条都要登录态。没有商户是 `20008`，文案键 `token.error`。商户行不存在是 `20006`，文案键 `member.not.found`。`binFlow` 不是空、`STANDARD`、`ENHANCED` 之一：`20027`，文案键 `param.invalid.format`，占位是 `binFlow`。空和 `STANDARD` 都剔除 Enhanced。`ENHANCED` 才把 Enhanced 放进列表。

候选要同时过这几关。商户没有 `agent_user_id`，两条都是空列表。有邀请码并且邀请码挂了价格组，只取该代理、该价格组、`agent_bin_config.status = 1` 的 BIN；否则取该代理全部启用 BIN。平台 `bin_config.status = 1` 且 `card_status = online`。`BinConfigServiceImpl.getByBinForMerchant` 对得上。所属 reseller 的 `bin_control.status = 1`，并且 `bin` 对得上。控制表的增删改不在这篇。

Enhanced 名单是 Nacos `uqpay.enhanced-kyc.bins`。`visibleOnList` 在 `includeAllBins` 为 false 时把这些 BIN 丢掉。

已经有卡，或者有一条没取消的邮寄，列表里的 `applyCard` 写成 0。月费字段另填。金额怎么算、怎么入账见最后一节。

## 未跑：客户端用 `cardHolderStatus` 决定去开卡页的确认按钮

`POST /api/v1/card/bins`

落点：`MerchantCardApiController.toApplyV2`。Android `SelectCardViewModel.loadCards` 调用，body 里 `binFlow` 固定是 `ENHANCED`。

上面的候选之外，还按请求头里的平台读 `t_system_config.title = card-bins-platform-blocklist`。名单里的 BIN 从 `bin` 数组删掉。平台 key 没有配置就不删。`/choices` 不读这份名单。

`cardHolderStatus` 由 `MerchantBinPreApplyCardVoAssembler.fillCardHolderStatus` 填，和 `KYC/profileFields` 同一套四态。只认本 BIN、同一 `channel_account_id` 上 `id` 最大的持卡人，以及本 BIN 最新一条 KYC。有持卡人按其状态。没有持卡人时，没有 KYC 是 `NOT_CREATED`，`kyc_status = 0` 是 `PENDING`，其余（含拒绝 4、通过 5 但没有持卡人）是 `INACTIVE`。不回传拒绝原因。命中持卡人时带本地主键 `cardHolderId`。

Android `SelectCardActivity.bindConfirmButton` 用这个状态换确认按钮。点下去仍调 `profileFields`，下一屏归 `07-KYC与持卡人`。

响应里还有钱包 `amount`、邮费 `courierFee`、状态为 `APPLY` 的卡张数 `applyCount`，以及虚拟卡、实体卡的已用张数和上限。张数不够时能不能拦住创建，归 `createCards`。

## Go for KYC

`POST /api/v1/card/choices`

落点：`MerchantCardApiController.cardChoices` → `MerchantCardChoiceSupport.listChoices`。Android `ChooseCardViewModel.loadCardChoices` 调用，body 里 `binFlow` 也是 `ENHANCED`。

在上面的候选里，每个渠道最多一张，顺序是 interlace，然后 uqpay。渠道槽始终按剔除 Enhanced 来挑，不让 Enhanced 占掉 uqpay 那一张。同渠道里 Nacos `merchant.card-choice.preferred-bin.interlace` 或 `.uqpay` 命中就用它，否则按 `bin_control.id` 升序取第一张。`bin_control` 还要挂着 `status = 1` 的渠道账户，并且渠道类型对得上。

`binFlow` 为 `ENHANCED` 时，再从 uqpay、已启用、代理可见、落在 Enhanced 名单里的控制行里，按 `id` 升序多加一张。这一张不读 preferred-bin。响应里只有这张带 `binFlow = ENHANCED`。最多三张。

`kycRequirementHint` 按渠道写死：interlace 是 `ID/Passport, Selfie`，uqpay 是 `ID/Passport`。

这条不调用 `fillCardHolderStatus`。组装时只有本 BIN 已有持卡人行才写入 `cardHolderStatus`，没有就空着。Android 选卡页的按钮是布局里的 `cvGoForKyc`，不按这个字段换文案。点下去同样先调 `profileFields`。

这次商户 `100985` 的三张卡，响应里 `cardHolderStatus` 都是空。屏幕上按钮都是 `Go for KYC`。点第三张只发 `POST /api/v1/KYC/profileFields`，`binConfigId` 是 `9`，接着是证件类型。没有 `applyPreview`，也没有 `createCards`。证件页归 `07-KYC与持卡人`。

## 未跑：客户端用 `40098` 决定去补资料，其它失败停在原页

这一格对过 `c61f995c7`（2026-11-18）。相对 `fe1350ff0`，UQPAY 创卡请求在 `card_limit` 大于等于 `0.01` 时把这一列写进报文。STX 再用同一列参加余额比较。

`POST /api/v1/card/createCards`

落点：`MerchantCardApiController.apply` → `MerchantCardOperationFacade.apply`。Android `VerifySecureKeyViewModel.applyCard` 调用，body 带 `payPassword` 和开卡参数。交易密码校验见 `05-交易密码`。

渠道成功之前就抛出的，不写 `order_record`，不写 `merchant_card`，不扣钱包。`apply` 没有包数据库事务，`catch` 里也不把已插入的行改成失败。渠道已经返回成功之后，本地先插入订单和卡，状态是 `SUCCESS`；虚拟卡 `card_status = 01`、`activation_state` 已激活，实体卡 `card_status = 03`、待激活。后面扣钱包或记平台入账再抛错，这两行留在库里，不会改回。渠道事后通知创建失败才把 `merchant_card.status` 写成 `FAILED`、`card_status` 写成 `05`，那一步归 `20-渠道发卡与回调`。

失败时会写库或缓存的只有一处：UQPAY 返回 `kyc_insufficient`。抛 `40098` 之前，Redis 写入 `kyc:uqpay:need-residence-sync:{merchantId}:{channelAccountId}:{bin}`，值是持卡人主键，24 小时。这个码不发开卡失败通知。其它业务失败会发失败通知，模板归 `27-邮件与告警`。通知失败不改变卡的结果。

拦住创建、并且不改卡表的判断：

| 条件 | 码 | 文案键 |
| --- | --- | --- |
| 代理价目或在线 BIN 对不上 | `40032` | `card.bin.not.open` |
| 钱包余额小于开卡费，STX 还要加上 `card_limit` | `40001` | `merchant.amount.too.little` |
| 虚拟卡或实体卡张数到上限 | `40087` / `40088` | `merchant.virtual.card.quota.exceeded` / `merchant.physical.card.quota.exceeded` |
| 本 BIN 没有持卡人 | `30203` | `cardholder.not.exist` |
| 开的是 Enhanced，或持卡人 BIN 是 Enhanced，但持卡人不是通过 | `40404` | `bbb.enhanced.holder.not.active` |
| UQPAY 且红名单国籍，本地没有地址证明 | `40098` | `kyc.poa.required.for.card` |
| 同一商户的钱包锁没拿到 | `40002` | `operation.in.progress` |
| Interlace 创卡不成功 | `30007` 或 `30039` | `apply.card.error` / `aaa.apply.card.contact.support` |
| UQPAY 创卡不成功，且不是 `kyc_insufficient` | `30007` | 文案用渠道原文 |
| 渠道类型不是这两家 | `CHANNEL_ERROR` | `unsupported channel type` |

出站方法是 `InterlaceClient.createCard` 和 `UqpayClient.createCard`。路径和回调归 `06-银行与渠道`、`20-渠道发卡与回调`。开卡费怎么算、扣哪一笔流水，见最后一节。

Android 只有 `40098` 另走补资料。其它失败停在校验页。成功响应的文案键是 `card.apply.success`，客户端再等 5 秒把 `applyCardSucceed` 设成 true。这一页还没跑。

## 未跑：客户端用 `availableAmount` 和 `applyFee` 决定去余额不足页

`POST /api/v1/card/applyPreview` 只报价。`POST /api/v1/card/createCards` 在渠道成功后按同一笔开卡费扣钱包。费率在后台怎么改，归 `21-费率与流水`。

开卡费是两段相加。基础费：虚拟卡取 `bin_config.base_card_fee`，实体卡取 `base_physical_card_fee`。加点只取 `merchant_add_point.apply_card` 这个固定额，不用 `apply_card_rate`、`apply_card_way`。字段是 NULL 就当 0。`openCardFeeWithRecharge` 同时算出的充值费，开卡这次不扣。

加点只加在这个商户第一张卡上。已经有任意 `merchant_card`（含注销 `05`、失败 `FAILED`），或者有一条没取消的 `card_ship_record`，加点改成 0，基础费照收。实扣在商户锁里判断。预览不持这把锁。

`/bins`、`/choices` 里的 `applyCard` 只是这段加点，不是开卡费合计。已开过就写成 0。Android 选卡页自己把基础费和 `applyCard` 相加，再向下保留两位。

`applyPreview` 的 `applyFee` 是基础费加加点，向下保留两位。`monthlyFee` 另给，不进 `applyFee`，开卡这次不扣。`availableAmount` 是当时的 USD 可用余额，也向下保留两位。Android `canCoverApplyFee` 用这两个数比较。够了才去验交易密码；实体卡且 `isShip = 1` 时去 `AddCardActivity`。不够去 `InsufficientBalanceActivity`。首页弹窗的 Active Now 用同一比较。

Enhanced BIN 且 `bin_control_transaction_limit.card_limit` 大于等于 `0.01` 时，创建还要把这一列加进余额比较。预览的 `applyFee` 不含它。预览显示够付，创建仍可能回 `40001`。

预览对不上可开 BIN 是 `40032`，文案键 `card.bin.not.open`。虚拟卡但 `bin_config.type` 不是 1：`40095`，`card.bin.not.support.virtual.card`。实体卡既没有 `support_physical_card = 1`，也不是平台和启用控制行都 `is_ship = 1`：`40061`，`card.bin.not.support.physical.card`。渠道解析失败：`40065`，`reseller.channel.not.configured`。不带 `binConfigId` 又没有可用的虚拟卡 KYC：`40132`，`card.apply.preview.no.kyc`。

渠道成功、本地卡行写入之后才入账。`order_record.type = create_card`，`status = 2`。`amount`、`total_amount`、`fee`、`apply_card_fee` 都是基础费加加点。`cregis_fee`、`cregis_apply_card_fee` 只是加点。`frozen_amount` 是 0，币种 USD。

然后 `merchant_wallet.amount` 减去这笔开卡费，并插一条 `merchant_transaction`：`type = create_card`，金额是开卡费的负数，`scene` 是 `fee`。流水上的 `balance_before`、`balance_after` 是可用余额加冻结。Enhanced 且这次 `card_limit` 大于 0 时，再减一笔钱包，流水 `type = card_opening_deposit`，`scene` 是 `tin`。同时写一条 `t_card_record`，类型也是 `card_opening_deposit`，`sub_type = stx-card-limit`，状态 2。这笔额度不进平台钱包。

平台钱包加上开卡费。`platform_transaction.type = create_card`，`amount` 是整笔开卡费，`plat_amount` 是加点，`vcc_amount` 是 0。扣款发生在插卡之后。这一步再失败，卡行留着，见上一节。
