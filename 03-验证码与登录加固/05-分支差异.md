# 分支差异

结论以分析分支为准。下面只记行为差别。`apidoc` 不当功能分支，没打开。2026-09-23 对过 `origin` 上这些分支。

## 卡平台后端

对照 `origin/main`、`origin/uat`、`origin/dev_enhanced`、`origin/feature/card-system-integration`。

`main`、`uat`、`feature/card-system-integration` 上，`EmailApiController`、`MerchantRegisterLoginOtpSendSupport`、`OpenApiPasswordLoginMfaSupport`、`MerchantEmailOtpCodeSupport`、`MerchantEmailOtpVerifyAttemptSupport`、`TestEmailCodeVerificationSupport`、`MerchantEmailCodeSendSupport`、`EmailCopyScenario` 和 `dev` 是同一个 blob。位数 8、600 秒、`/verify` 不删码、错码 `20050` 起，这三条没有另一套。

`dev_enhanced` 上位数、有效期、错码锁定和那三个文件仍是同一个 blob。少的是 Apple：

- 没有 `linkAppleSignIn` 的发码。这个 type 落到不认识的类型上：不发信、不写 Redis，接口仍成功。
- `/verify` 对这个 type 也当不认识，不查 Redis，直接成功。
- 没有 `matchForAppleLink`。
- 文案里没有 Link Apple Sign-In，也没有已登录的 Connect / Disconnect Apple Sign-In。

注册、登录、重置、`linkGoogleSignIn` 的发码和验码，和 `dev` 一样。

## H5

分析分支 `test`。`src/api/email.js` 在 `origin/dev`、`origin/kyc-bank`、`origin/text-amendment-09-20` 上无差异。验证码页 `src/pages/auth/verifyCode/index.vue` 的格子数都是 8。

`origin/dev`、`origin/text-amendment-09-20` 的这一页和 `test` 无差异。

`origin/kyc-bank` 不同：注册、重置发码失败后不返回上一页。`test` 上大约 800 毫秒后 `navigateBack`，和 Android 一样。注册验码通过后，`kyc-bank` 还把 `product` 带到设密页，`test` 不带。

## WebApp

`origin/newmain`、`origin/newuat` 的 `src/lib/apiEndpoints.ts`、`src/lib/api.ts`、`src/app/auth/page.tsx`、`src/shared/components/CodeBoxes.tsx`、`src/features/settings/components/GoogleSignInEmailVerifyModal.tsx` 和 `newtest` 是同一个 blob。格子数仍是 8。

「还在，这次不写」是无。本功能在这三处不涉及其他分支。
