# 代码分析

分析分支：`vtron_java_server` `dev`。2026-09-23 `git pull` 已是最新。

第一遍只写注册、登录、重置登录密码，以及 Google、Apple 回访 link 的发码和验码。改邮箱、交易密码、提币、开卡的 type 不在这里展开。

## 位数和有效期

`MerchantEmailOtpCodeSupport`。位数是常量 `EMAIL_OTP_CODE_LENGTH = 8`，纯数字，可以有前导 0。注释写明不可配置。`RandomUtil.randomNumbers(8)`。

Redis TTL 是 `EMAIL_OTP_TTL_SECONDS`，600 秒。注册、登录、重置、两条 link 都用这个值。

Nacos `virtronex.api.otp-override.enabled=true` 且收件邮箱等于配置的 email 时，这封信改用配置的固定码。其它邮箱仍是随机码。

测试环境另有一条只在校验时生效：`test.env=true` 且 `test.email.code` 非空时，Redis 里必须已经有码，输入和 Redis 一致算通过，输入和配置码一致也算通过。发信时写入 Redis 的仍是随机码。`TestEmailCodeVerificationSupport.matches`。

连续输错默认 3 次，窗口和锁定都是 1800 秒。只计对不上，过期或不存在不计。锁定期间不能验，也不能重发。注册的锁不影响登录，按场景 Redis 键加邮箱分开。Nacos 键是 `merchant.email-otp.max-fail`、`fail-window-seconds`、`lock-seconds`。计数键 `merchant:email_otp:fail:`，锁定键 `merchant:email_otp:lock:`，后面接场景键和邮箱。`MerchantEmailOtpVerifyAttemptSupport`。

## 未登录发码

`POST /api/v1/email/send`。`EmailApiController.sendEmail`。不要求 Bearer。body 要邮箱和 `type`。缺了是 `FORM_FORMAT_ERROR`。

公开 type 和 Redis 键、文案：

| type | Redis 键 | `EmailCopyScenario` |
|------|----------|---------------------|
| `register` | `merchant:register:email:code` | `MERCHANT_REGISTER`，主题 “{} Account Register”，方式 “Register for {}” |
| `login` | `merchant:login:email:code` | `MERCHANT_LOGIN`，“{} Account Login” / “Log in to {}” |
| `reset` | `merchant:reset:email:code` | `MERCHANT_RESET_LOGIN_PASSWORD`，“{} Account Login” / “Reset Login Password” |
| `linkGoogleSignIn` | `merchant:google:signin:link:email:code` | `MERCHANT_GOOGLE_SIGNIN_LINK`，方式 “Link Google Sign-In” |
| `linkAppleSignIn` | `merchant:apple:signin:link:email:code` | `MERCHANT_APPLE_SIGNIN_LINK`，方式 “Link Apple Sign-In” |

主题里的 `{}` 由 `EmailCopyResellerSupport.resolve` 按 reseller 填。信本身由 Feign 调 `virtronex-email`。模板归 `27-邮件与告警`。

发之前先看这个邮箱是否在 OTP 锁里，再走 `OpenApiPreLoginRateLimiter.checkEmailSendRateLimit`。次数见 `02-邮箱注册登录` 的 `04`。

- `register`：邮箱已经有商户，不发信，`20005` `member.exist.email`。新邮箱才发。平台凭证或请求里带了邀请码时，用邀请码解析出发信 reseller；BU 凭证且没带码，用签名 reseller。邀请码落点见 `02-邮箱注册登录`。
- `login`、`linkGoogleSignIn`、`linkAppleSignIn`：先按 `email` 列找商户，没有再按 `username`。BU 凭证两边都加 `reseller_id`。找不到先睡 1.5 到 2 秒，再抛 `20007` `password.error`。码发到商户绑定邮箱，Redis 的 field 用请求里的那个邮箱字符串。
- `reset`：找不到商户同样先睡再抛 `40092` `password.reset.failed`。找到则发到请求里的邮箱。

不认识的 type 不发信、不写 Redis，仍返回成功。`sendEmail` 末尾那条日志是 `unsupported type silently ignored`。

返回体带 `senderDomain`，按 reseller 解析发信域名。

## 未登录验码

`POST /api/v1/email/verify`。要邮箱、`code`、`type`。type 不是上表那五种，直接成功，不查 Redis。

是这五种时，先过 `OpenApiPreLoginCommitScene.EMAIL_VERIFY` 的提交限流，再 `verifyOtpWithoutConsume`。Redis 没有码是 `20003` `code.invalid`，不记失败。对不上按剩余次数：

- 还剩 2 次：`20050` `email.otp.fail.two.left`，英文 “2 attempts remaining”
- 还剩 1 次：`20051` `email.otp.fail.one.left`，英文 “1 attempt remaining”
- 第 3 次：写锁定并清计数，`20052` `email.otp.verify.locked`，英文 “Please try again in 30 minutes.” 这句写死，不按剩余秒数拼。`data.lockRemainingSeconds` 才是剩余秒

默认 3 次时对不上不会落到 `20002`。`20002` `code.error` 用在剩余次数不是 1 或 2，例如把 `max-fail` 配得更大。对上了只清失败次数和锁，不删验证码。登录或重置真正提交时才消耗。

Android 把 `20002`、`20003`、`20050`、`20051`、`20052` 的 `message` 放在格子旁边，这几个码不弹 toast。`02-邮箱注册登录` 只错了一次，旁边就是 “2 attempts remaining”，对得上第一次失败。

## 和验证器谁先

`OpenApiPasswordLoginMfaSupport`。密码登录 `match`：body 里有 `googleCode` 就只验验证器；没有则验登录邮箱码，开了验证器也可以走邮箱码。两头都空是 `20003`。对上之后先记成 `Pending`，业务成功才 `claim` 删掉 Redis 里的码。失败 `release` 不删。登录接口本身见 `02-邮箱注册登录`。

`linkWithPassword` 用 `matchForGoogleLink`、`matchForAppleLink`。这个商户开了验证器就必须带 `googleCode`，带邮箱码也不行，`40014` `google.code.required`。没开验证器才验对应的 link 邮箱码。身份令牌归 `04-第三方登录`。

## 已登录的两个接口

`POST /sendAfterLogin`、`POST /verifyAfterLogin` 要 Bearer，商户 `status` 必须是 1，否则 `TOKEN_ERROR`。

`verifyAfterLogin` 若 type 是上面五种公开类型，直接 `10013` `email.type.error`，让客户端改走 `/verify`。

`sendAfterLogin` 里 `changeEmail` 把码发到 body 里的新邮箱。其它 type 发到当前绑定邮箱。不认识的 type 同样返回成功但不发信。这一遍不列那些 type。

## 对账

`02-用户视角` 里的 `POST /api/v1/email/send`、`POST /api/v1/email/verify` 就是上面两节。Android 一进 `EmailVerifyActivity` 就发码，`Continue` 先验码。进页之前的 `POST /api/v1/auth/check/password`，以及验码通过后的 `POST /api/v1/auth/login`，已在 `02-邮箱注册登录` 的 `04`。

点开发信域名提示打开的是静态页 `https://file.virtronex.com/static/cant-find-email-prototype.html`，query 带 `platform=android` 和返回的 `senderDomain`。不是卡平台接口。60 秒倒计时是客户端本地的，Redis 里的码仍是 600 秒。

`03-管理后台` 没有要补的接口。员工登录的 `POST /email/sendCheckEmailWithoutEmail`、银行 `AdminLoginEmailController` 都不是这四个接口。邮件发送日志归 `27-邮件与告警`。
