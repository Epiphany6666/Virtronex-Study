# 银行与渠道

分析分支：卡平台 `vtron_java_server` `dev`，银行 `virtronex_bank_service` `test`。2026-09-23 `git pull`，两边都已是最新。

## 银行

不涉及。`EmailApiController`、`MerchantRegisterLoginOtpSendSupport`、`MerchantEmailCodeSendSupport` 不调用 `bank-api`，也不接收 `bank-callback`。

银行 `bank-api` 自己有 `POST /api/v1/email/send`，Feign 打到 `bank-email` 的 `POST /email/send`。卡平台这四个接口不走那条。

## 发卡渠道

不涉及。上面三个类没有 Interlace、UQPAY、SunRate 的调用。

`MerchantEmailCodeSendSupport.recordCardOtpEventIfNeeded` 只在交易密码和提币时写事件，那两类不在这一遍。注册、登录、两条 link 在 `MerchantRegisterLoginOtpSendSupport` 里另写 `card_otp_event`。注册的 `otp_kind` 是 `registration`，`event_type` 是 `merchant.register`。登录和两条 link 的 `otp_kind` 是 `login`，`event_type` 是 `merchant.login`。重置不写这张表。

## 其他三方

发的是邮箱验证码，场景是注册、登录、重置登录密码、Link Google Sign-In、Link Apple Sign-In。服务是 `virtronex-email`。`EmailFeignClient` 的服务名就是 `virtronex-email`，方法 `POST /email/send`。经 `EmailSenders.recording` 落到 `email_send_log`。记录页归 `27-邮件与告警`，模板正文也归那里。

Nacos `virtronex.email.dev.skip-feign=true` 时不调 Feign，接口仍成功，验证码照常进 Redis。默认 `false`。Feign 失败是 `20029` `email.error`。

不调 Cregis，也不调 FCM。
