# 代码分析

分析分支：`vtron_java_server` `dev`。2026-09-23 `git pull` 已是最新。

设置、修改、重置见前三节。校验次数见下一节。`02`、`03` 里多出来的接口见文末对账。

## 入口

`POST /api/v1/customer/modifyAccessDetails`。`MerchantApiController.update`。要 Bearer。没有登录态是 `20008`，文案键 `api.token.required`。商户行没有是 `20006` `member.not.found`。`type` 空或不认识是 `10014` `update.type.error`。

不读商户 `status`，也不读 KYC。`MerchantUpdateVo` 没有 KYC 字段。`*PayPassword*` 这几个类里也没有 KYC。重置不看证件、也不看审核状态。

Android `SetSecureKeyActivity` 提交 `type`、`code`、`payPassword`。账户安全页和开卡前的缺口会进这页。界面见下一篇 `02`。

新码必须匹配 `^[0-9]{6}$`。否则 `40010` `pay.password.set.error`，英文 “SecureKey must be a 6-digit number.”。写入是 bcrypt，列 `merchant.pay_password`。

## 设置和修改

`createPayPassword`、`updatePayPassword` 走同一个分支。不看原来有没有码，也不验旧码。设过再走设置，或没设过走修改，都会直接盖掉。

第二道是 `matchGoogleOrEmailWithoutConsume`。body 里有 `googleCode` 就只验验证器：没开是 `40028` `google.not.on`，码错是 `10012` `google.code.incorrect`。没有 `googleCode` 就验邮箱码，开了验证器也可以。两头都空是 `20003` `code.invalid`。绑定本身见 `06-谷歌验证器`。

邮箱码的 Redis 键按 type 分开，对不上另一边的码：

- 设置：`merchant:create:pay:password:email:code`
- 修改：`merchant:update:pay:password:email:code`

field 是商户绑定邮箱。发码和输错次数见 `03-验证码与登录加固`。

对上之后 `OpenApiDeferredMfaSupport.run` 先占住这道校验，再 `updateById`。邮箱码在写入前删掉。写入抛错会把码放回 Redis，TTL 重新按 600 秒。验证器没有这道删除。

## 重置

`resetPayPassword`。`pay_password` 还是空的，`40072` `pay.password.not.set`，英文 “SecureKey has not been set. Please set it first.”。

材料只有新的 6 位码和邮箱码。`verifyEmailCode`，键 `merchant:reset:pay:password:email:code`。`googleCode` 不看。不验旧码。

成功后同样 bcrypt 盖掉 `pay_password`，并 `clearVerifyAttempts` 清掉校验失败计数。计数规则见下一节。邮箱码同样是写入前删、失败放回。

## 校验次数

`MerchantPayPasswordVerifyService.verify`。独立入口是 `POST /api/v1/auth/check/verifyPayPassword`，body 只有 `payPassword`。Android `VerifySecureKeyActivity` 调这一条。开卡、提币里的调用这一遍不列表。

按商户 id 计数，不按动作分开。失败键 `merchant:verify_pay_pw:fail:`，锁定键 `merchant:verify_pay_pw:lock:`。Nacos `merchant.verify-pay-password.max-fail` 默认 5，`fail-window-seconds` 和 `lock-seconds` 默认都是 900 秒。窗口从第一次输错开始算。

空字符串是 `10010` `form.format.error`，不计数。还没设过是 `40072`，也不计数。已经锁了先拒绝，不再比对。

对上了清失败次数和锁。对不上按剩余次数：

- 还剩 4 次：`20053`，英文 “4 attempts remaining”
- 还剩 3 次：`20054`，“3 attempts remaining”
- 还剩 2 次：`20055`，“2 attempts remaining”
- 还剩 1 次：`20056`，“1 attempt remaining”
- 第 5 次：写锁定并清计数，`40073` `pay.password.verify.locked`，英文 “Too many incorrect attempts. SecureKey temporarily locked.” `data.lockRemainingSeconds` 是剩余秒。这句不写 15 分钟

默认 5 次时对不上不会落到 `20034`。`20034` `pay.password.error`，英文 “Incorrect SecureKey.”，用在剩余次数不是 1 到 4，例如把 `max-fail` 配得更大。

Android 把 `20034`、`20053` 到 `20056`、`40073` 的 `message` 放在输入框下面，这几个码不弹 toast。

自助重置成功，以及运营重置成功，也清这两把键。设置和修改成功不清。

## 对账

`02-用户视角` 里的 `POST /api/v1/customer/modifyAccessDetails` 就是上面的设置、修改、重置。`createPayPassword` 对上设置成功的绿条。`resetPayPassword` 对上 “Security Password Reset” 那一页。`updatePayPassword` 在第 1 次里，和设置共用一个分支；这次修改停在校验错误，设密和成功吐司没走到。

设两位时 “Confirm SecureKey” 和 “Mismatch, Please Re-enter” 都在 `SetSecureKeyActivity` 本地比，不一致不发请求。重置前的 “Reset SecureKey?” 也是本地确认。邮箱验证码页的发码、验码归 `03-验证码与登录加固`，这篇不重写。

修改在账号安全里先走 `POST /api/v1/auth/check/verifyPayPassword`，红字 “4 attempts remaining” 就是 `20053`。这一步对上之后，客户端才去发 `updatePayPassword`。改密接口本身不验旧码。

`03-管理后台` 多两条，上面没有单独写。

`POST /email/sendCheckEmailWithoutEmail`，`EmailController.sendCheckEmailWithoutEmail`，要已登录。弹窗 `Get Code` 的 `type` 是 `platformResetMerchantPayPassword`。码发到当前员工邮箱，Redis 键 `platform:reset:merchant:pay:password:email:code`。不改 `merchant`。邮件模板归 `27-邮件与告警`。员工登录用的也是这个路径，但 type 不是这一个，登录发码不在这篇。

`POST /merchantAddPoint/resetPayPassword`，`MerchantAddPointController.resetPayPassword`，权限 `bu:merchantAddPoint:resetPayPassword`。服务 `MerchantPayPasswordResetServiceImpl.resetPayPassword`。`merchantId` 或邮箱码空着是 `merchantPayPasswordReset.param.required`。商户不在数据范围里是 `record.notFound`。邮箱码先验员工那把键。员工开了验证器才要谷歌码，空着是 `google.code.required`，不对是 `google.code.invalid`；没开就跳过，和这次弹窗没有谷歌码一致。通过后 `pay_password` 写成 `NULL`，并删掉 `merchant:verify_pay_pw:fail:`、`merchant:verify_pay_pw:lock:` 这两把键。不看原来有没有码，也不写新的 6 位。这次没有点 `Confirm`，所以没看到 “SecureKey reset successfully”，库里的列也没动。
