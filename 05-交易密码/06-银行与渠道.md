# 银行与渠道

分析分支：卡平台 `vtron_java_server` `dev`，银行 `virtronex_bank_service` `test`。2026-09-23 `git pull`，两边都已是最新。

## 银行

不涉及。`MerchantPayPasswordVerifyService.verify`、`MerchantApiController.update` 里设置、修改、重置这三支，以及 `MerchantPayPasswordResetServiceImpl.resetPayPassword`，都不调用 `bank-api`，也不接收 `bank-callback`。

银行仓里搜过 `payPassword`、`pay_password`、`SecureKey`、`createPayPassword`。没有对应接口。`bank-api` 的 `SysEmailConfigType` 把模板名 `sendPayPasswordCodeEmail-en` 标成通知类，只是本仓发信时选配置，卡平台这几条不走那里。

## 发卡渠道

不涉及。上面这些类没有 Interlace、UQPAY、SunRate 的调用。

C 端发码成功后会另写本库 `card_otp_event`，`channel_type` 是 `platform`，不是上面三家。见下一节。

## 其他三方

不调 Cregis，也不调 FCM。

校验 `POST /api/v1/auth/check/verifyPayPassword` 不发信。

C 端设置、修改、重置之前的邮箱码，是已登录的 `POST /api/v1/email/sendAfterLogin`。`EmailApiController.sendAfterLogin` 调 `MerchantAuthedEmailOtpSendSupport.sendToBoundEmail`，再进 `MerchantEmailCodeSendSupport.sendCode`。三支 type 都发到商户绑定邮箱。服务是 `virtronex-email`，`EmailFeignClient` 的 `POST /email/send`。模板文件都是 `sendPayPasswordCodeEmail-en`。场景文案：设置 “Set SecureKey”，修改 “Change SecureKey”，重置 “Reset SecureKey”。模板正文归 `27-邮件与告警`。

`emailDevSkipFeign` 为真时，Feign 之前就返回，信不发，下面这张表也不写。

Feign 成功后 `CardOtpEventServiceImpl.recordMerchantSecureKeyEmailCode` 插入 `card_otp_event`。`otp_kind` 是 `SecureKey`。`event_type`：设置 `merchant.create.pay.password`，修改 `merchant.update.pay.password`，重置 `merchant.reset.pay.password`。`card_id` 写成 `-`。插入失败只打日志，不把发码打成失败。后台看这张表归 `22-管理后台-客户与卡/06-卡OTP`。

运营重置的 `Get Code` 是另一封。`PlatformEmailSendService.sendCheckEmailWithoutEmail`，type `platformResetMerchantPayPassword`，发给当前员工邮箱。同样是 `virtronex-email` 的 `POST /email/send`，模板是通用的 `sendCodeEmail-en`，场景 “Reset Merchant SecureKey”。不写 `card_otp_event`。
