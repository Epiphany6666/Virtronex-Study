# 代码分析

分析分支：`vtron_java_server` `dev`。2026-09-23 `git pull` 已是最新，`b28b4c9e2`。

这一遍只写介绍里那几类验证码怎样进 `virtronex-email`。位数、验码、输错锁定见 `03-验证码与登录加固`。模板正文、维护邮件、告警、银行邮件留到第二遍。

`virtronex-email` 自己不认 `EmailCopyScenario`。调用方填好模板名、主题、方式文案和验证码，再 Feign 调 `POST /email/send`。

## 邮件服务

`EmailController.send` 把 `SendEmailDTO` 交给 `EmailServiceImpl.sendEmail`。

收件地址先过 `PlainEmailAddressValidator.requirePlainEmail`。空、超 254、格式不对、带换行或邮件头字样，直接拒绝。

Thymeleaf 按 `fileName` 找 `templates/` 下同名模板，后缀 `.html` 由引擎补。这一遍用到两个：

| 模板 | `EmailType` | 谁用 |
|------|-------------|------|
| `sendCodeEmail-en` | `info` | 注册、登录、改密、验证器、Google/Apple 连接，以及后台强制解绑 |
| `sendPayPasswordCodeEmail-en` | `notify` | 设置、修改、重置交易密码 |

渲染时写入 `code`、`way`、`nickName`。Logo 内嵌目前注释掉了，信里没有 `cid:p01`。

`smtpHost` 和 `smtpUsername` 都有值时用请求里的 SMTP，否则用本服务的 `spring.mail.*`。自定义端口空则 465。465 走隐式 SSL，其它端口走 STARTTLS。发件人显示名优先自定义 `smtpNickName`，空则用全局昵称，再空则是 “your account”。

主题已含 ` Account ` 或 ` Card ` 时原样发出。这一遍的主题都是 “{} Account …”，不会再加 `[昵称]` 前缀。

成功打 `[email] 邮件发送成功`。失败把异常抛回调用方。C 端收成 `20029` `email.error`。

## C 端怎样填这封信

`MerchantEmailCodeSendSupport.sendCode`。`virtronex.email.dev.skip-feign=true` 时只打警告并返回，不调 Feign，也不写 `email_send_log`。本地 `application.yml` 这项目前是 `true`，Nacos 同键可以盖掉。Redis 里的码由调用方在 `sendCode` 返回之后写入，跳过 Feign 时码仍在。

没跳过时：

1. `fileName` 看 type。`createPayPassword`、`updatePayPassword`、`resetPayPassword` 用 `sendPayPasswordCodeEmail-en`，其余用 `sendCodeEmail-en`。未登录那五条走的是不带 type 的重载，所以也是 `sendCodeEmail-en`。
2. `EmailSubjectWaySupport` 把场景解析好的 subject、way 写进 DTO。`{}` 来自 `EmailSenderDomainResolver.resolveNickName(resellerId)`：这个 reseller 启用了自定义 SMTP（`smtpHost` 非空）就用 `smtpNickName`，空则用全局 `spring.mail.nickName`。这里不按邮件类型挑配置。
3. `ResellerEmailConfigApplySupport` 再按模板类型查 `reseller_email_config`。先专属类型，没有则 `auto`，再没有取该 BU 启用行里 id 最小的。`resellerId` 空则不填，邮件服务用全局 SMTP。交易密码模板类型是 `notify`，其余是 `info`，和上一步昵称查询不是同一次。
4. `RecordingEmailSender` 先插 `email_send_log` 待发送，Feign 成功改成功，失败写失败原因再抛出。当前策略是外发都落库。有 `merchantId` 时操作者是该商户，否则是 system，带上 reseller。

交易密码发成功后，`sendCode` 另写一条 `card_otp_event`。注册、登录、两条 link 的记录在各自的发送方法里，不在 `sendCode`。

## 未登录

`POST /api/v1/email/send` 进 `MerchantRegisterLoginOtpSendSupport.trySendPublicOtpByType`。谁能发、失败码见 `03-验证码与登录加固`。发信本身：

| type | 场景 | 收件 | 操作者 |
|------|------|------|--------|
| `register` | `MERCHANT_REGISTER` | 请求里的新邮箱 | system，reseller 是邀请码或签名解析出的那个。商户还不存在 |
| `login` | `MERCHANT_LOGIN` | 商户绑定邮箱 | 该商户 |
| `reset` | `MERCHANT_RESET_LOGIN_PASSWORD` | 请求里的邮箱 | 该商户 |
| `linkGoogleSignIn` | `MERCHANT_GOOGLE_SIGNIN_LINK` | 商户绑定邮箱 | 该商户 |
| `linkAppleSignIn` | `MERCHANT_APPLE_SIGNIN_LINK` | 商户绑定邮箱 | 该商户 |

Feign 失败则不写 Redis。成功后写入，TTL 600 秒。

`EmailApiController` 成功时用 `okWithSenderDomain`。域名来自 `EmailSenderDomainResolver.resolveSenderDomain`：先看这个 reseller 启用配置的 `smtp_username`，含 `@` 才取 `@` 后面；没有再看 `smtp_from`，再没有用全局 `spring.mail.emailFrom`。都解析不出时是 `xxxx.com`。Android 只在登录和注册把这块收成 “Didn't receive the email?”。`Check spam folder` 打开的是静态页 `https://file.virtronex.com/static/cant-find-email-prototype.html`，查询参数带这个域名，页上写成 `noreply@` 加域名。不是卡平台接口。倒计时结束后的 `Resend` 还是上面这条 `POST /api/v1/email/send`。

## 后台强制解绑

`POST /email/sendCheckEmailWithoutEmail`。`PlatformEmailSendService.sendCheckEmailWithoutEmail`。要已登录员工。员工没配邮箱是 `email.notConfigured`。

| type | 场景 | Redis 键 |
|------|------|----------|
| `platformForceUnbindMerchantGoogle` | `FORCE_UNBIND_MERCHANT_GOOGLE` | `platform:reset:merchant:google:force:unbind:email:code` |
| `platformForceUnbindMerchantApple` | `FORCE_UNBIND_MERCHANT_APPLE` | `platform:reset:merchant:apple:force:unbind:email:code` |

文案在 `PlatformEmailCopyScenario`，`{}` 用操作者所属 BU 的发信昵称，没有则用后台全局 `spring.mail.nickName`。模板仍是 `sendCodeEmail-en`。码先写入 Redis，再 `ManageEmailFeignSupport.send`。跳过 Feign 时在写日志之前返回，所以 Redis 有码，`email_send_log` 没有。没跳过时先插待发送，再调 `virtronex-email`。同一个接口里还有充值、冻结、重置验证器等 type，不在这一遍。

## 发信日志查询

`POST /log/emailSend/page`。`LogController.emailSendPage`。权限 `bu:log:emailSend:list` 或 `main:log:emailSend:list`。页面上的 Detail 不再请求接口，用这一页已经返回的行。行里没有验证码。

查的是 `email_send_log`，按 id 倒序。收件邮箱、模板名、标题、失败短码是包含匹配。触发方类型、收件方类型是相等。状态 `1` 待发送、`2` 成功、`3` 失败。日期由页面收成当天 `00:00:00` 到结束日的下一天 `00:00:00`。

范围在 `EmailSendLogScopeMapper`。平台员工不加条件。代理只留收件方是自己名下商户的行，或触发方就是这个代理的行。`denyAll` 时一条都不出。

测试环境 Main Admin 的角色菜单没有 `sys_menu` 2290，路由没注册，这次请求没有发出。见 `03-管理后台`。
