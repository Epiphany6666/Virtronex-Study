# 分支差异

结论以分析分支为准。下面只记行为差别。

## 卡平台后端

对照 `origin/main`、`origin/uat`、`origin/dev_enhanced`、`origin/feature/card-system-integration`。`apidoc` 不当功能分支，没打开。

`AuthController` 在 `main`、`uat`、`dev_enhanced` 上是同一个 blob，和 `dev` 不同。三个分支上登录成功仍然只返回 `token`、`expires_in`、`merchant_id`。`dev` 改成 `ComprehensiveKycSupport.sessionPayload`，综合 KYC 用户多一个 `binConfigId`。四个路径名没有增减：`login`、`check/password`、`check/emailExists`、`logout`、`check/verifyPayPassword`。

`MerchantApiController` 在 `main`、`uat`、`dev_enhanced` 上没有 `bankFunction`，也没有 `isComprehensiveKyc`。`dev` 上注册在 `isComprehensiveKyc = 1` 时直接发会话；那三个分支的注册方法还在，但没有这段。

`feature/card-system-integration` 相对 `dev`，`MerchantApiController` 多出来的是 `KYCinfo` 里的 `bankInvited`。注册、忘记密码、`bankFunction` 没有另开接口。`KYCinfo` 不在本功能。

`MerchantRegisterService` 相对 `main` 有 14 行差异，和上面的综合 KYC、会话字段是同一批改动，没有另一套注册。

## H5

分析分支 `test`。

- `origin/dev` 的 `src/pages/auth` 和 `test` 无差异。
- `origin/kyc-bank` 的注册页会调 `probeBankFunction`，`bankFunctionEnabled` 为 true 时展示 Fiat / Digital 两张卡，并把 `product` 传到验证码页、再传到设密页。`test` 的 `src` 里没有 `bankFunction`。验证码页在 `kyc-bank` 上拿掉了注册和重置密码发码失败后等待 800ms 再返回上一页。登录页只给 logo 加了打开 vConsole 的点击，登录请求没有变。
- 设密页 `src/pages/auth/setPassword/index.vue` 相对 `test` 是加 118 行、删 8 行。密码规则没有变。多出来的是：密码框回车跳到确认框，已经能提交就直接提交；Google 注册时确认框回车再跳到邀请码。注册请求固定带 `isComprehensiveKyc: 1`。返回有 token 时，`product` 是 Fiat 并且带了 `binConfigId`，就先准备 Fiat 开卡 KYC，成功进入那条 KYC 入口，失败则提示后去钱包首页；其他有 token 的注册直接建会话并去钱包首页。没有 token 则提示注册成功，1.2 秒后回到登录页。`test` 仍是跳到注册成功页。
- `origin/text-amendment-09-20` 只改设密页标签：文案键从 `newPassword` 换成 `setYourOwnPassword`。

## WebApp

`origin/newmain`、`origin/newuat` 的 `src/app/auth`、`src/features/auth` 和 `newtest` 无差异。
