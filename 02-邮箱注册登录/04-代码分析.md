# 代码分析

分析分支：`vtron_java_server` `dev`。公共签名在 Filter 里完成，见 `19-OpenAPI会话`。下面每个接口都是先验签。

`AuthController` 本篇只写 `login`、`check/password`、`check/emailExists`、`logout`。`check/verifyPayPassword` 归 `05-交易密码`。

`MerchantApiController` 本篇只写 `register`、`forgetPassword`、`bankFunction`。

## 注册

`POST /api/v1/customer/register`

谁调用：Android 注册在验证码和设密之后才发这个接口。第一包缺 app id，停在发码失败，请求没发出，见 `02-用户视角` 第 7 步。第二包补上凭证后，设密点继续把这个接口发出去了，见第 9 步。

落点：`virtronex-api/.../merchant/MerchantApiController.java` `registMember` → `MerchantRegisterService.registerMemberFirst`。

只验签，无 Bearer。缺邮箱、验证码或密码：`10010`，文案键 `param.empty.error`。签名上下文没有 reseller：`30005`，文案键 `api.sign.required`。

控制器先做两道限流。下面是代码里的默认值，Nacos 可以覆盖。

`OpenApiPreLoginCommitRateLimiter` 场景 `REGISTER`：每次请求都计数，含失败。同一 IP 每分钟 20、每小时 120；同一设备每分钟 10、每小时 60；同一邮箱每小时 30。窗口分别是 60 秒和 3600 秒。

`OpenApiRegisterCommitRateLimiter.checkBeforeRegister` 只挡成功次数，失败不加。自然日内同一 IP 18 次、同一设备 27 次。小众邮箱域名每天 45 次；`gmail.com`、`qq.com`、`163.com` 这类公共域名不计这一维。`example.com` 不在这张白名单里。成功插入后再 `recordRegisterSuccess`。超限是 `20042`。

登录、忘记密码的提交限流是同一套类、另一组数：IP 每分钟 20、每小时 120，设备每分钟 10、每小时 60，邮箱每小时 30。`email/verify` 宽一点：IP 每分钟 30、每小时 180，设备每分钟 15、每小时 90，邮箱每小时 40。

`check/password` 不走上面这套，走 `OpenApiPreLoginRateLimiter` 的探针：同一 IP 每分钟 10、每小时 60，同一设备每分钟 5、每小时 30。模拟器上连点错误密码出现的 “Too many requests. Please try again in 1 minute.” 是这一档，见 `02-用户视角` 第 16 步。

然后 `registerMemberFirst(cmd, scopedResellerId)`。平台凭证把 `scopedResellerId` 传 `null`。平台凭证指 `reseller_api.id` 在 `reseller.api.platform-ids` 里，不是 `reseller_id = 0` 这一列本身。两套判断差在哪，见 `BU对照.md`。

`registerMemberFirst` 在一个事务里，顺序是：

1. 邮箱 trim 后为空：`10010`。
2. `MerchantSensitiveEmailBlockSupport.rejectIfBlocked`。
3. `merchant.email` 已存在：`20005` `member.exist.email`。插入前再查一次，防并发。
4. 验证码空、Redis 没有、或比对失败。Redis 键是 `Constants.MERCHANT_EMAIL_REGISTER`。没有码或 Redis 没有：`20003` `code.invalid`。比对失败走 `MerchantEmailOtpVerifyAttemptSupport.recordFailureAndThrow`。发码和位数见 `03-验证码与登录加固`。
5. 密码必须匹配 `^(?=.*\d)(?=.*[a-z])(?=.*[A-Z]).{8,20}$`，否则 `40009` `password.set.error`。
6. 解析邀请码，见下一节。
7. BCrypt 后 `MerchantServiceImpl.initMerchantByEmail` 插入 `merchant`。
8. `merchantAddPoint`、`merchantWalletInit`。
9. 注册事务提交后再建充币地址。事务回滚则不建。见 `06-银行与渠道`。
10. `merchantStatisticService.increaseRegister`，并删掉注册验证码。

`initMerchantByEmail` 写上的字段：

| 字段 | 值 |
|------|----|
| `username`、`email` | 规范化后的邮箱 |
| `real_name` | 邮箱前三段 + `****@` + 域名 |
| `password` | BCrypt |
| `status` | `1` |
| `head_url` | 配置 `headerUrl` 里随机一个，空则空串 |
| `is_init_address` | `"1"` |
| `p_id` | 邮箱注册传的是 `null`，不写上级 |
| `is_comprehensive_kyc` | 请求里为 `1` 才写 `1`，否则 `0` |
| `agent_user_id` | 邀请码行上的 `agent_admin_user_id`，大于 0 才写 |
| `agent_invite_code_id` | 邀请码行的 id，大于 0 才写 |
| `reseller_id` | 邀请码行的 `reseller_id`，大于 0 才写 |
| `register_via` | 邮箱注册传 `null`，不写。Google / Apple 才写 |

`merchantWalletInit`：`sys_currency.status = 1` 的每个币种插一条 `MerchantWallet`，`amount` 和 `frozen_amount` 为 0。

`merchantAddPoint`：有代理且邀请码带 `price_group_id` 时，先用该代理这个价格组里 `type = INITIAL_ADD` 且启用的配置。没有则用全局 `system_config`（`config_level = 1`、同样的 type、启用）。费率菜单归 `21-费率与流水` 和 `25-分销商代理与BIN`。

成功之后控制器看 `isComprehensiveKyc`：

- 为 `1`：`issueRegisterSession`。注册验证码已经验过，不再做登录那道 MFA。会话里的 `resellerId` 用商户自己的，不用签名上的。`login_method = password`，`second_factor = email_otp`，写入 `merchant_login_log`。返回 `ComprehensiveKycSupport.sessionPayload`：`token`、`expires_in`、`merchant_id`；只有综合 KYC 才再加 `binConfigId`（Nacos 里的 BIN 查 `bin_config.id`，查不到就省略这个字段）。
- 不传或为 `0`：成功 data 为空。类注释写明客户端再调 login。

`bankFunctionEnabled` 不放进这次响应。

### 邀请码绑到哪

`MerchantRegisterInviteCodeSupport.requireAgentInviteCode`。`agentInviteCode` 优先于 `inviteCode`。

查码范围：`scopedResellerId` 为 `null` 或 `0` 全库查；否则只查该 `reseller_id`。登录找商户不走这道，只认白名单里的平台凭证。见 `BU对照.md`。

| 请求 | 用哪条码 |
|------|----------|
| 没传码，BU 凭证 | 该 BU 的默认邀请码。这个 BU 没有默认码才用 Nacos `merchantInviteCode` |
| 没传码，平台凭证 | 只用 Nacos |
| 传了码且在范围内命中 | 用这条。`explicitFromRequest = true` |
| 传了码但范围内没有 | BU 有默认码就退回默认码；没有默认码再试 Nacos。平台凭证直接试 Nacos。`fellBackToDefault = true` |
| 退完仍没有行 | `20010`，文案键是 `invite.code.invalid`（枚举名 `AGENT_NOT_EXIST`） |

邮箱注册多一道：BU 凭证下，请求里明确命中的码，其 `reseller_id` 必须等于签名 BU，否则同样 `20010`。退回默认码或 Nacos 的结果不走这道（`explicitFromRequest` 为 false）。Google / Apple 注册连退回的结果也要属于签名 BU，那两条不在本篇展开。

绑到商户上的是邀请码行的 `reseller_id`、`agent_admin_user_id`、`id`，以及用 `price_group_id` 去取开户加点。不是把签名里的 reseller 直接写进商户。

## 登录

`POST /api/v1/auth/login`

谁调用：Android 在邮箱验证码通过后才发。这次没有进到验证码页。登录按钮先调的是下面的 `check/password`，见 `02-用户视角` 第 3 步。

落点：`virtronex-api/.../auth/AuthController.java` `login`。

没有身份或没有 reseller：`30005` `api.invalid.context`。没有客户端上下文：`10010`，文案键也是 `api.invalid.context`。缺用户名或密码：`10010` `api.username.password.required`。邮箱格式不过 `MerchantEmailAddressSupport.requirePlainEmail`：`10019`。敏感邮箱拦截后再限流，场景 `LOGIN`。

找商户：

- 平台凭证：只按 `email` 全局找一条。
- 其他凭证：`reseller_id = 签名 reseller`，并且 `username` 或 `email` 等于这个邮箱。

找不到：`20007` `password.error`，登录日志原因 `USER_NOT_FOUND`。不告诉客户端账号不存在。

`status` 不是 `1`：业务码仍是 `20007`，文案键是 `user.disabled`。

密码：`MerchantLoginPasswordAttemptService.verify`。已锁定：`40091` `login.password.locked`。密码空或 BCrypt 不匹配：`20007`，并累计失败。默认第 6 次失败上锁，计数窗口和锁定时长默认都是 900 秒（`merchant.login-password.max-fail`、`fail-window-seconds`、`lock-seconds`，可被 Nacos 覆盖）。成功则清掉失败计数和锁。

第二道校验在密码通过之后，`OpenApiPasswordLoginMfaSupport.match`：

- 带了 `googleCode`：优先走 TOTP。`google_verify` 要有 `google_status = 1` 的行。密码登录这条查询不强制 `type = 2`。没有开启的行：`40028` `google.not.on`。码的比对和占用见 `06-谷歌验证器`。
- 没带 `googleCode`、带了 `code`：邮箱验证码，Redis 键 `MERCHANT_EMAIL_LOGIN`。已开验证器仍然可以用邮箱码，不会因此拒绝。
- 两个都空：`20003` `code.invalid`。

匹配成功先 `claim`，再 `OpenApiSessionService.createSession`。会话里的 reseller 用 `merchant.reseller_id`，不用签名上的 0。会话创建失败会 `release` 这道校验。成功 data 与综合 KYC 注册同一套 `sessionPayload`。写 `merchant_login_log`，`login_method = password`。

类注释写明：登录不查持卡人、卡 KYC、银行开户。`bankFunctionEnabled` 不在登录结果里。

## 登录前的两个探针

### `POST /api/v1/auth/check/password`

谁调用：Android 登录页点 `Submit`，且邮箱格式已通过。这次包里没有 app id，停在 “Application credentials are missing”。见 `02-用户视角` 第 3 步。

只验签，不发 token。缺用户名或密码：`10010`。然后 `MerchantLoginProbeService.checkPasswordOpenApi`：先探针限流，再按平台或 BU 找到商户，调用同一个 `verify`。所以输错也会累计登录密码锁定。找不到商户同样是 `20007`。成功 data 为 `true`。

### `POST /api/v1/auth/check/emailExists`

`MerchantLoginProbeService.checkMerchantExistsOpenApi` 是空方法，只打日志。控制器固定返回 `true`。类注释写明这是过渡期，前端即将下线。不查库。

## 退出

`POST /api/v1/auth/logout`

从 `Authorization: Bearer` 取出 token，有 token 就 `OpenApiSessionService.removeSession`。没有 token 也返回成功。不改 `merchant`。

## 忘记密码

`POST /api/v1/customer/forgetPassword`

谁调用：Android 重置密码要先过验证码和设密页。第一包只打开了填邮箱的一页，请求没发。第二包设密通过后发出了这个接口，见 `02-用户视角` 第 13 步。

落点：`MerchantApiController.forgetPassword`。只验签。

缺邮箱或新密码：`10010` `param.empty.error`。限流场景 `FORGET_PASSWORD`。按 `email` 全局找商户，不按签名 BU 过滤。找不到：`40092` `password.reset.failed`，不返回「账号不存在」。

新密码先走 `MerchantLoginPasswordSupport.validateNewLoginPassword`，策略失败用这个方法抛出的码。

第二道校验 `MerchantSecondFactorAuthSupport.matchForgetPasswordWithoutConsume`：

- 已开启谷歌验证器并且请求带了 `googleCode`：比对 TOTP。不对是 `10012` `google.code.incorrect`。
- 其余情况（没开验证器，或开了但没带 `googleCode`）：邮箱验证码，Redis 键 `Constants.MERCHANT_EMAIL_RESET_CHECK`。

通过后更新 `merchant.password`，并 `clearAttempts` 清掉登录密码的失败计数和锁。不建会话，不建充币地址。

## 注册页的银行入口探针

`POST /api/v1/customer/bankFunction`

只验签，无 Bearer。落点：`MerchantApiController.bankFunction` → `PreLoginBankFeatureSupport.isVisible`。

请求体可选 `agentInviteCode`、`inviteCode`，前者优先。返回 `bankFunctionEnabled`。

定哪个 BU：

- 没填码：平台凭证得到 `null`，结果是 false。BU 凭证用签名 reseller。
- 填了码：在当前凭证范围内点查 `agent_invite_code`。命中就用码上的 `reseller_id`。没命中时，平台凭证是 false，BU 凭证仍用签名 reseller。

不走注册那套默认码和 Nacos 回退。码无效不抛 `20010`。

最后 `MerchantBankFeatureSupport.isEnabledForReseller`：`reseller_id` 为空或 `<= 0` 则 false；否则看 `reseller.bank_function_enabled` 是否为 `1`。

类注释写明：不做发码、注册、登录会话。登录之后的银行入口不在这个接口，而在 `KYCinfo` 的 `MerchantBankFeatureSupport.isAvailable`（还要看有没有 KYC 记录）。那条不在本篇。

分析分支里，H5 `test`、WebApp `newtest`、Android `dev`、iOS `release` 都搜过 `bankFunction` 和 `bank_function`，没有调用。Android 注册页这次走查也没有打到它。`kyc-bank` 上的注册页会调，记在 `05-分支差异`。
