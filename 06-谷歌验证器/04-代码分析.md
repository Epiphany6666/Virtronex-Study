# 代码分析

分析分支：`vtron_java_server` `dev`。2026-09-23 `git pull` 已是最新。`02`、`03` 里多出来的接口见文末对账。

四个接口都在 `GoogleApiController`。没有登录态是 `20008` `token.error`，英文 “Session expired. Please log in again.”。商户行没有是 `20006` `member.not.found`，英文 “Account does not exist.”。不读商户 `status`，也不读 KYC。行按 `merchant_id` 加 `type = 2` 找，`type` 是商户这把验证器，不是渠道类型。

动态码是 6 位，30 秒一步，HMAC-SHA1。`GoogleAuthenticator.matchCode` 认过去 2 步、当前步、未来 1 步。对上了不占住这一步，同一窗里可以再对。`10017` `google.code.already.used` 还在错误码表里，这四个接口的匹配不会返回它。

登录、改密、资金动作谁来调 `MerchantSecondFactorAuthSupport`，这一遍不收。

## 二维码

`POST /api/v1/google/getQrcode`。`getQrcode`。新密钥 20 字节，Base32 大写。二维码字符串是 `otpauth://totp/`，账号名优先用不含 `@` 的用户名，否则用邮箱 `@` 前面那段。`issuer` 传的是空字符串，链接里没有 `issuer`。

已经开启时仍发一把新密钥，`alreadyEnabled` 为 true。这一步不写 `google_verify`。

## 状态

`POST /api/v1/google/info`。`info`。`google_status` 是 `1` 才算开着，返回 `status = 1`，带上 `bind_time`、`bind_device`、`last_verify_time`。没有行，或者状态不是 `1`（含关掉之后的 `0`），对外都是 `status = 2`，不带那三个时间。没有单独的是否已绑定接口。

## 预检

`POST /api/v1/google/checkCode`。`checkCode`。body 只有 `googleCode`。没开启是 `40028` `google.not.on`，英文 “Google authentication is not enabled.”。码空是 `10015` `google.code.empty.error`，英文 “Google authentication code is required.”。对不上是 `10012` `google.code.incorrect`，英文 “Incorrect authenticator code.”。对上返回 true，不改 `last_verify_time`，也不改密钥。

## 保存

`POST /api/v1/googleVerify/save`。`save`。绑定设备写成请求的 `User-Agent`，超过 255 个字符就截断。

| 当前 | 动作 | 下一状态 | 谁 |
|------|------|----------|----|
| 没有行，或状态不是 `1` | `googleStatus=3`，新密钥加该密钥的动态码 | 写成 `1`，记下绑定时间、设备和上次验证时间 | 用户 |
| 已经是 `1` | 再传 `3` | 不变 | 用户，被拒绝 |
| 已经是 `1` | `googleStatus=2`，旧动态码、新密钥、新动态码 | 仍是 `1`，密钥换成新的，绑定时间和设备重写 | 用户 |
| 不是 `1` | 传 `2` | 不变 | 用户，被拒绝 |
| 已经是 `1` | `googleStatus=0` | 写成 `0`，密钥、绑定时间、设备、上次验证时间清空，行还在 | 用户 |
| 任意 | 传 `1`，或不是 `0`、`2`、`3` | 不变 | 用户，被拒绝 |

`3`：已经是 `1` 则 `40011` `google.already.on`，英文 “Google Authenticator is already enabled. Please use Change Device instead of binding again.”。动态码空是 `10015`。密钥空或对不上是 `10012`。有旧行（例如关过）就改那一行，没有才插入。不看邮箱码。

`2`：不是开启中是 `40028`。旧码、新密钥、新码有一个空是 `20003` `code.invalid`，英文 “The verification code has expired. Please resend.”。旧码不对是 `10020` `google.old.code.error`，英文 “Incorrect code from your old authenticator.”。新码不对是 `10021` `google.new.code.error`，英文 “Incorrect code from your new authenticator.”。不看邮箱码。

`0`：不是开启中是 `40028`。body 里有 `googleCode` 就只验旧密钥的动态码，错了是 `10012`，不会改去验邮箱。没有动态码才验邮箱码，键 `merchant:google:close:email:code`，field 是绑定邮箱。发码、位数、输错次数见 `03-验证码与登录加固`。两头都空是 `20003`。通过后逻辑删除，不删行。邮箱码在写入前删掉，写入抛错会放回 Redis。动态码没有这道删除。

`googleStatus` 为 `1` 或其他值是 `10010` `form.format.error`。这句英文是 “The file format is not supported.”，不是在说文件。

## 对账

`02-用户视角` 里的 `POST /api/v1/google/getQrcode`、`POST /api/v1/google/checkCode`、`POST /api/v1/googleVerify/save` 就是上面三节。绑定成功页对上 `googleStatus=3`。换设备旧码页对上 `checkCode`，标题写成 “Verify New Authenticator App”，校验的仍是旧设备动态码，这次没有提交。关闭弹窗只带 `googleCode`、`googleStatus=0`，和上面「有动态码就只验动态码」一致，这次点了 `Cancel`。

安装页的 `Install`、`Continue`，以及关闭弹窗上的三条红字，都在客户端本地，不发请求。`Continue` 不要求本机已经装上验证器。

账号安全上的 `Enable Now` / `Modify`，以及 “Account Protection: High”，用的是本机记下的 `googleStatus`。绑定成功后客户端自己改成开启。这次没有打 `POST /api/v1/google/info`。

`03-管理后台` 多两条，上面没有单独写。

`POST /email/sendCheckEmailWithoutEmail`，`EmailController.sendCheckEmailWithoutEmail`，要已登录。弹窗 `Get Code` 的 `type` 是 `platformResetMerchantGoogle`。码发到当前员工邮箱，Redis 键 `platform:reset:merchant:google:email:code`。不改 `google_verify`。邮件模板归 `27-邮件与告警`。员工登录、强制解绑 Google 或 Apple 登录用的也是这个路径，但 type 不是这一个，不在这篇。

`POST /merchantAddPoint/resetGoogleAuthenticator`，`MerchantAddPointController.resetGoogleAuthenticator`，权限 `bu:merchantAddPoint:resetGoogleAuthenticator`。服务 `MerchantGoogleAuthenticatorResetServiceImpl.resetGoogleAuthenticator`。`merchantId` 或邮箱码空着是 `merchantGoogleAuthenticatorReset.param.required`，英文 “Required parameters are missing.”。商户不在数据范围里是 `record.notFound`，英文 “Record not found or operation not permitted.”。邮箱码先验员工那把键。员工开了验证器才要谷歌码，空着是 `google.code.required`，不对是 `google.code.invalid`；没开就跳过，和这次弹窗没有谷歌码一致。通过后把 `type = 2` 且 `google_status = 1` 的那一行改成 `0`，密钥、绑定时间、设备、上次验证时间清空，行留下。改不到恰好一行是 `google.notEnabled`，英文 “Google Authenticator is not enabled.”。这和 C 端没开启时的 `40028` `google.not.on` 不是同一句。不写 `google_verify_log`。这次没有点 `Confirm`，所以没看到 “Google Authenticator reset successfully”，库里 `100985` 的状态仍是 `1`。
