# 银行与渠道

分析分支：卡平台 `vtron_java_server` `dev`，银行 `virtronex_bank_service` `test`。2026-09-23 `git pull`，银行已是最新。

卡平台这道门不调用 `bank-api`，也不接收 `bank-callback`。`OpenApiSignatureFilter` 里出现的 `bankFunction` 只是放行路径的名字，过滤器本身不请求银行。

## 银行

银行 C 端另有一道门，在 `bank-api` 自己的进程里，类注释写明对齐卡项目过滤器。两边不共用密钥表，也不共用 Redis 前缀。

- 类：`bank-api` 的 `CEndOpenApiFilter`
- 范围：`/api/v1/**`，排除 `/api/v1/partner`。Partner 的 `X-Partner-Sign` 归 `30-卡银行Partner对接`
- 密钥：`BusinessApiCredentialService.findEnabled`，表 `business_api`，不是卡平台 `reseller_api`
- 参签：`appId + timestamp + nonce + canonicalBody`，HMAC-SHA256 小写十六进制。multipart 的 body 按空字符串签
- nonce：`BankRedisKeys.nonce`，默认前缀 `virtronex_bank:nonce:`。卡平台是 `reseller_api:nonce:`
- 时间戳：10 位及以内当秒，更长当毫秒。卡平台只按秒
- 失败都是 HTTP 200 明文 JSON。缺任一签名头是 `openapi.missing.headers`，未知 app id 是 `openapi.invalid.appId`，时间窗外是 `openapi.timestamp.expired`，nonce 重用是 `openapi.nonce.reused`，签名不对是 `openapi.invalid.sign`。这五条的 `ErrorCode` 都是 `401`。解密失败是 `openapi.decrypt.failed`，该加密却是明文是 `openapi.encrypted.body.required`，这两条是 `400`。卡平台验签失败是业务码 `30005`，设备头失败是 `10010`
- 这一层不查 Bearer。银行会话键是 `virtronex_bank:session:`，不是 `reseller_api:session:`

## 发卡渠道

不涉及。`OpenApiSignatureFilter`、`OpenApiAuthService`、`OpenApiSessionService` 没有 Interlace、UQPAY、SunRate 的调用。

## 其他三方

不涉及。这道门不调 Cregis，不发邮件，也不调 FCM。`removeSession` 只把该商户的推送绑定在本库标成失效，见 `04-代码分析`。后台新建密钥时的员工邮箱码由 `virtronex-manage` 发，模板归 `27-邮件与告警`。
