# OpenAPI 会话

`/api/v1/**` 进 `virtronex-api` 之前的公共门。`OpenApiSignatureFilter` 只拦这个前缀。验签通过之后，按配置解密请求体，登录前的路径放行，其余路径用 Bearer 查 Redis 会话。出站加密在 `OpenApiCryptoResponseBodyAdvice`。

谁在用：H5、Web、Android、iOS 调卡平台 C 端接口时都走这道门。各接口自己的业务参数不在这里写。后台密钥页在业务用户的「API Key Management」。没有踢掉某个 C 端会话的页。

不包含：

- 邮箱注册、登录、重置密码的业务判断。见 `02-邮箱注册登录`
- 发码和验证码位数。见 `03-验证码与登录加固`。后台新建密钥时发给当前员工的码，模板归 `27-邮件与告警`
- Google、Apple 身份令牌怎么验。见 `04-第三方登录`。过滤器只把对应的登录路径当成登录前放行
- 版本检查返回什么。见 `01-启动与版本`
- 扫码解析出什么。见 `34-扫码邀请码`
- 渠道回调。那是 `virtronex-callback`，不进这个 Filter
- 商户站 JWT 怎么签发。这里只写 OpenAPI 会话，以及它和商户站会话怎样互踢
- 银行自己的 `CEndOpenApiFilter` 和 Partner 的 `X-Partner-Sign`。方向写在 `06-银行与渠道`，Partner 归 `30-卡银行Partner对接`

分析分支：卡平台后端 `vtron_java_server` `dev`，银行 `virtronex_bank_service` `test`。2026-09-23 `git pull`，卡平台与银行都已是最新。界面以 Android `dev` 为准，H5、Web、iOS 不跑。

前置数据：

- 启用中的 `reseller_api`。平台凭证看 `reseller_api.id` 是否在 `reseller.api.platform-ids`，不看 `reseller_id` 是不是 0。测试 Android 用的那条见 `BU对照.md`
- 客户端要能签出 `X-App-Id`、`X-Timestamp`、`X-Nonce`、`X-Sign`。第一包缺 app id 时，登录和注册停在原页，红条是 “Application credentials are missing. Please try again later.”
- Redis。nonce 键 `reseller_api:nonce:`，会话键 `reseller_api:session:`，活跃指针 `reseller_api:active:`
- 后台新建密钥要当前员工的邮箱码。开了验证器才要谷歌码。凭证框只出现一次

对照文档 `docs/virtronex/OpenAPI-签名规范.md`。和代码不一致时以 `OpenApiSignatureFilter`、`OpenApiAuthService`、`OpenApiSessionService` 为准。差别在 `04-代码分析`。

Figma 没有单独的签名页。页 `0:1` 上 “Login has expired” 是 node `158:1820`。这次模拟器没点到 401 弹窗。
