# 管理后台

卡平台后台 `virtronex-manage`，分支 `dev`。银行后台没有这套密钥页。查过 `virtronex-ui/src/views` 里的 `apiKey`、`api-cache`、`monitor/online`。

C 端商户的 OpenAPI 会话没有后台页。`views/monitor/online` 是后台员工自己的在线会话，能强制退出员工，不碰 `reseller_api:session:`。

## 1. 进入密钥页

业务用户列表 `views/businessUser/info` 的行操作「API Key Management」。权限 `bu:reseller:apiKey`。打开 `/businessUser/apiKey`，查询带 `userId`、`resellerId`、`entityName`。

同一页右上角另有「Refresh API Key Cache」，权限 `bu:reseller:reloadApiCache`。它不在密钥页里。

测试后台曾经从这里进过密钥页，新建过一把密钥。凭证框出现过一次。编辑和停用没点。刷新缓存按钮点过，`POST /reseller/api-cache/reload` 返回 200。响应体是加密的，没读出刷新了几条。

## 2. 列表

`POST /reseller/api-key/list`。列是 App ID、名称、回调地址、状态、联系人、联系邮箱、备注、创建时间。状态 1 是 Enabled，否则 Disabled。

服务端 `ResellerApiBuServiceImpl.list` 要求平台员工。密钥挂在打开的那个 `resellerId` 上。这个页面不能把密钥改成平台凭证。平台凭证是 `reseller_api.id` 落在服务端白名单里，见 `BU对照.md`。

## 3. 新建

按钮 “New API Key”。表单有名称、回调地址、联系人、电话、邮箱、备注。必填的是邮箱验证码，类型 `platformApiKey`。当前员工开了验证器才多一个谷歌码。测试员工这次没开。

`POST /reseller/api-key/add`。服务端生成 app id、secret 和两对 RSA 密钥，secret 和请求私钥加密后写入 `reseller_api`，状态直接是启用，并按这个 app id 刷新缓存。

成功后弹出 “API Credentials (save now)”。警告是 “These credentials are shown only once. Copy and store them before closing.” 框里是 App ID、App Secret、请求公钥、响应私钥，可以导出。列表之后不再返回 secret。

C 端要等这把密钥写进包里才能验签。停用或改资料走 `POST /reseller/api-key/update`，同样要验证码，并刷新这一条缓存。停用后验签是 `api.invalid.app`，见 `04-代码分析`。这次没在页面上点停用。

## 4. 全量刷新缓存

`POST /reseller/api-cache/reload`。平台员工，权限 `bu:reseller:reloadApiCache`。从库重载全部 `reseller_api` 进 Redis，并删掉库里已经没有的键。新建和修改单条时已经刷新过那一条，这个按钮是全量的。

## 本步没有

- 踢掉某个 C 端商户的 OpenAPI 会话
- 在页面上把密钥标成平台凭证
- 密钥页的编辑、停用。按钮在，这次没点
