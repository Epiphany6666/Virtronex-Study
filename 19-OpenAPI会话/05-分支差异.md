# 分支差异

结论以分析分支为准。下面只记行为差别。`apidoc` 不当功能分支，没打开。

## 卡平台后端

对照 `origin/main`、`origin/uat`、`origin/dev_enhanced`、`origin/feature/card-system-integration`。

`OpenApiAuthService`、`OpenApiSessionService`、`OpenApiClientContextResolver`、`OpenApiCryptoResponseBodyAdvice`、`OpenApiCryptoProperties`、`PlatformCanonicalJson`、`MerchantGlobalSessionRevocationSupport`、`ResellerApiBuServiceImpl`，以及后台页 `views/businessUser/apiKey/index.vue`，这四条分支和 `dev` 是同一个 blob。验签算法、会话键、互踢、密钥页没有另一套。

只有 `OpenApiSignatureFilter` 的登录前名单不同。

- `main`、`uat`、`feature/card-system-integration` 是同一个 blob。相对 `dev` 少了 `POST /api/v1/customer/bankFunction`。这三条分支的 Java 里也没有这个接口的实现，只有过滤器文件提到这个路径。没带 Bearer 打这条路径时，过滤器按要会话处理，返回 HTTP 401。`dev` 把它放在登录前名单里，不要求 Bearer。
- `dev_enhanced` 的名单再少 Apple 的三条：`/api/v1/auth/apple/login`、`linkWithPassword`、`register`，同样没有 `bankFunction`。这个分支没有 `AppleSignInController`。`main`、`uat`、`feature/card-system-integration` 有这个控制器，名单里也有这三条，和 `dev` 一样。

注释里「固定英语」那两行在 `dev` 上缩短了，方法仍是 `Locale.US`。

## H5

分析分支 `test`。

`origin/dev` 的 `src/utils/api/openApiSign.js`、`openApiRequest.js`、`openApiCrypto.js`、`request.js` 和 `test` 无差异。

`origin/kyc-bank` 的签名文件和 `test` 无差异。`request.js` 在本地 `DEV` 下，传输失败会用同一段密文重新组签名头再发，最多两次，间隔 300ms、800ms。路径最后一段是 `send`、`forgetpassword`、`linkwithpassword` 这类写操作时不重试。生产构建不走这段。`test` 没有重试。

`origin/text-amendment-09-20` 的 `request.js` 只给 `baseRequest` 加了可选 `timeout`。签名没变。

## WebApp

`origin/newmain`、`origin/newuat` 的 `src/lib/openapi/openApiSign.ts`、`src/lib/api.ts`、`src/lib/openapi/deviceId.ts` 和 `newtest` 是同一个 blob。签名串没变。

差别在 `src/lib/openapi/credentials.ts`。那两个分支把各 BU 的 app id 混淆后写在文件里。`newtest` 改成读 `NEXT_PUBLIC_OPENAPI_APP_ID`。凭证内容不抄进笔记。

## 银行、Android、iOS

「还在，这次不写」是无。本功能在这三处不涉及其他分支。
