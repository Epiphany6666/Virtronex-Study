# 启动与版本

C 端问该不该升级。卡平台接口只有 `POST /api/v1/app/version`，落点 `AppVersionApiController.getVersion`。按这次签名的 app id 和 body 里的 `type` 查 `app_version`。返回里的 `updateType`：0 是强制更新，1 是非强制。服务端不拿它和客户端当前版本比。

谁发起：Android 不在启动页发。`StartupActivity` 只看本地登录态，约 2 秒后没登录进登录页。版本请求在 `LoginActivity` 和 `MainActivity` 创建时发出，body 只有 `type`。本机 `versionCode` 118 高于平时返回的 114，框不出现。返回的 `versionCode` 高于本机时，强制框盖在登录页上，没有 Cancel。H5 生产环境比的是静态 `version.json`，不调这个接口。Web 的常量在，`src` 里没有调用。

分析分支：卡平台后端 `vtron_java_server` `dev`，银行 `virtronex_bank_service` `test`。2026-09-23 `git pull` 均已是最新。界面只跑 Android `dev`。H5 生产环境比的是静态 `version.json`，不调这个接口。Web 的常量在，`src` 里没有调用。这两端和 iOS 不另开模拟器或浏览器。

前置数据：

- 启用中的 `reseller_api`。签名 app id 没有版本行时，回退到 `reseller_id = 0` 且启用、`id` 最小的那条。测试库是 id 1，不是 android-tst 的 id 5。和验签白名单不是同一套
- `app_version` 一行：`type`、`version_code`、`update_type`。Android 只有返回的 `version_code` 大于本机才弹框。后台编辑也是再插一行
- 测试库用 android-tst 查 `android`、不传 `version_code`，落到 `app_version.id = 16`，`update_type = 1`，`version_code = 114`

Figma 页 `0:1` 上有启动屏和版本升级提示。
